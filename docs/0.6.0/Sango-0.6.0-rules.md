# Sango 0.6.0 — 人口、徵兵、訓練、AP 與四季音樂

日期：2026-09-07。基準為本次上傳的 `Sango-source(1).zip`，不是先前聊天交付包。
本文件描述這次實際寫入 Source 的規則。以下平衡數字是第一版採用值，可以調整；不代表所有數字都已經過自然遊玩驗收。

## 1. 版本與保留項目

Java 17、LibGDX 1.13.1、SimpleUI 1.1.2 的正式依賴維持不變。遊戲版本 0.6.0，Android versionCode 7，GameState schema 5，Save document schema 1。

保留六勢力、42 城、68 路、地形相機、舊六城劇本、三槽存檔、戰報、季節經濟、空城佔領、任務結束後自由征戰。沒有加入真實武將名單、武將 UI、帶兵規模擴張、安民命令或音樂解鎖機制。

## 2. 每月勢力共用行動力

新局第一個月玩家與各個活躍非中立 AI 統一 3 AP；不是先計算高初始民心再發 7～9 點。後續月份以自己全部領地的民心總和發放：

| 民心總和 | AP |
|---:|---:|
| 0～199 | 3 |
| 200～399 | 4 |
| 400～649 | 5 |
| 650～899 | 6 |
| 900～1149 | 7 |
| 1150～1499 | 8 |
| ≥1500 | 9 |

這是整數階梯表，不把它宣稱為連續光滑函數。城池不以人口加權；敵方、中立城不算入我方。新增零民心領地不會降低「總和」，但會降低後述全勢力平均民心。

發放時機為月底所有處理及日期推進後。當月民心改變、切城、預估、讀檔不回補 AP，剩餘不跨月累積。滅亡勢力及沒有領地的勢力剩餘 0；中立不執行命令。舊存檔原本 2/9 或 2/3 保留到下一個月底，不強迫月中改為新曲線。

玩家沿用 GameState 原本的月額度快照。AI 使用 FactionState.aiActionPointsPerTurn／aiActionPointsRemaining，透過共同入口扣點及發放，避免將玩家額度重複儲存在兩處。

## 3. 本城、全國民心與新兵

全勢力平均民心採各城等權；有效民心 E = 本城民心 × 60% + 全勢力平均民心 × 40%。內部保留百分之一點，避免 79.99 過早變成 80。

目前新兵 Training = 50；Morale = 30 + floor(E × 0.4)，範圍 30～70。有效民心 50 對應新兵士氣 50。30～70 是這次選用的初版參數，不是新增一條已永久鎖定的規格。Training 不直接受民心影響。

例如一城民心 100、另一城 0，前者有效民心 80、新兵士氣 62，而不是拿到 70。若十城僅一城 100、其餘 0，該城有效民心 64、新兵士氣 55。治理單城仍有優勢，但不能完全避開全國低民心的代價。

徵兵後品質 = (原兵數 × 原品質 + 新兵數 × 新兵品質) / 合計兵數。取消固定訓練 −5、士氣 −5。千名 100 品質的士兵補入千名 50 品質新兵，結果為 75；兩千名 100 再加千名 50，結果為 83.333333。原部隊品質比新兵差時，平均值可能上升，而不是一律扣分。

## 4. 玩家自行決定徵兵量

內政「徵兵」開啟 modal，提供滑桿、數字輸入、±100、最少／最多。預設選擇 200 人，但不再是固定徵兵量。只有確認成功才扣資源；取消、超量、零人、金糧不足或沒有 AP 均不消耗。

人口基礎上限 = floor(10 × √當前城市人口)。實作使用 long 整數平方根校正，避免浮點邊界差一人。

| 當前人口 | 人口曲線上限 |
|---:|---:|
| 10,000 | 1,000 |
| 30,000 | 1,732 |
| 50,000 | 2,236 |
| 80,000 | 2,828 |
| 100,000 | 3,162 |

實際上限再取人口曲線（含武將能力倍率）、10,000 人硬上限、人口 −2,000、金錢可負擔數、糧食可負擔數、總兵力 int 剩餘空間的最小值。

人口 2,000 以下不能徵兵；人口 2,001 最多只能徵 1 人。保護的是「徵完後至少保留 2,000 人」，不是只檢查點按前的人口。先前口述「低於一萬不能徵兵」的誤述沒有實作。

每次徵兵 1 AP，人口扣實際徵兵數。金、糧各 ceil(徵兵數 / 2)，延續原本 200 兵需 100 金、100 糧的成本比例。奇數人數各向上取整；拆成多次不會變便宜。UI 同時顯示人口保留量、資源上限、新兵素質、全軍平均變化及費用。

10,000 是安全硬上限，不表示現有每座城都能徵到一萬；按現在人口容量及基礎曲線，通常先受到人口或資源限制。徵兵上限與野戰軍出征上限是兩件事。

## 5. 部分兵力接受訓練

現階段使用抽象執行武將 DEFAULT：徵兵能力 100%、Training Coverage 20,000 人、受訓部分 Training +5／Morale +5、新兵 Training 50。這些屬性互相獨立。未來可建立真正武將的 OfficerCommandProfile，再傳入現有規則，不需要先做武將 UI。

一次訓練仍為 1 AP、50 金。令全軍兵數 N、覆蓋 C = min(N, 20,000)，目前平均品質 Q：

新平均品質 = Q + C/N × min(5, 100−Q)。

先把受訓部分限制在 100，再和未受訓部隊平均；不能把 C/N×5 加到全軍後才截成 100，兩種算法在接近滿值時不同。

| 城內兵力 | 受訓人數 | 品質 50 時的全軍單次增量 |
|---:|---:|---:|
| 10,000 | 10,000 | +5 |
| 20,000 | 20,000 | +5 |
| 50,000 | 20,000 | +2 |
| 100,000 | 20,000 | +1 |
| 2,000,000（測試極值） | 20,000 | +0.05 |

例如十萬兵、Training 99，本次只能升為 99.2，而非全軍直接 100。零兵拒絕訓練；Training、Morale 均滿時不扣資源。

模型保留全軍平均，沒有逐一記錄某個士兵是否剛被訓練；覆蓋部隊視為平均品質的代表樣本。這是輕量近似，不是逐兵模擬。

素質以百萬分之一點固定小數保存：原 training／morale 加上 trainingFraction／moraleFraction。徵兵、訓練、出征、增援、敗退、佔領、copy-on-write 與存讀均保留小數。UI 向下顯示兩位小數，低於 0.01 的變化仍存在。最接近 100 時以一個微小單位處理取整停滯。

既有戰鬥強度公式仍使用已完成的整數訓練／士氣；小數是持久的成長進度。未更動戰術倍率、士氣倍率及城防倍率。

## 6. 每年人口成長／流失

每年十二月底結算一次，在軍糧、洪災、收入、戰鬥與 AI 命令之後，日期推進之前。預覽及讀檔不增長人口。

| 有效民心 | 年度比率 |
|---:|---:|
| 0～未滿 20 | −4% |
| 20～未滿 40 | −2% |
| 40～未滿 60 | 0% |
| 60～未滿 80 | +2% |
| 80～100 | +4% |

初算人口 × 比率，朝零取整；年度變化限制為 −3,000～+5,000。年度負向變化不使人口低於 1,000，但若舊存檔已低於 1,000，不憑空補人。正成長不超過城市容量；已超容量的舊人口只停止成長，不在讀檔或結算時強制裁切。其他既有災害扣人口規則沒有改成同一個底線。

保留本次 Source 42 城原本 38,000～70,000 初始人口，不將其硬套進先前聊天示意的小／中／大城人數。為各城新增 Definition.populationCapacity，初版依初始人口的 1.5 倍向上取到一萬人，實際為 60,000～110,000；數值已寫在 cities.json，可逐城調整。

全勢力平均不包含敵人。中立沒有共同君主，因此其人口只看該城民心。AI、玩家、中立各城均進行年度人口結算；月報列出我方各城變化。

人口變化是出生、死亡及遷移的抽象總結果，不是城際人口守恆轉移模型。沒有新設出生率、戶籍、難民來源或安民命令。現行改善民心手段不足仍是後續設計議題。

## 7. AI 同規則，策略與玩家決策分開

AI 的徵兵、訓練、資源及 AP 都經共用 DomesticActionService／FactionActionPointRules；不再沿用免費定額增兵。AI 出征也扣 1 AP、100 糧，保留 400 守軍，最低出征 400、最多 1,000，每勢力最多一支野戰軍，與玩家相同。

三個月集結倒數保留為 AI 決策節奏，不是額外免費命令。每月按現有 AP 執行：需要且可負擔時補兵至約 1,800、訓練至目標品質，再改善內政；有合適前線且集結完成才出征。不會為了花光 AP 無限空轉。月報顯示 AI 的實際命令用量。

「同規則」不表示 AI 已有完整最優策略、和玩家同樣的人類資訊判斷或完整戰略指令選擇。自然遊玩平衡尚未驗收。

本次 source 不包含四首 MP3 或任何圖資。表中的檔名只定義播放器的預期本機資產路徑；使用者自行補入前，必須先確認權利、公開散布條件與平台規範。季節安排依使用者的描述及確認，不是 Assistant 實際聽感判讀。

月份跨季以兩秒重疊 Crossfade：舊曲淡出、新曲淡入。同季地圖、內政、月報、戰報、遊戲設定間不重播。跨月命令成功後立即更新目標季節。快速連續換曲沿用現有音量，不把舊曲重置為全音量；完成後釋放舊串流。

曲目循環播放，但 MP3 檔案自身循環邊界未製作成無縫，不宣稱原曲 loop 無接縫。四曲響度未另作校準。

Lobby 及 Settings 增加「音樂鑑賞」。提供四曲列表、播放／暫停、上／下一首、時間、音樂開關。此模式不推進月份、不花 AP、不修改戰局。退出回 Lobby 時恢復 Lobby 曲；從遊戲 Settings 開啟者，退出恢復當前季節。平台 pause/resume 與手動暫停分開處理，不能由平台恢復自動取消手動暫停。

目前為單曲循環，不包含拖拉進度、曲目解鎖、隨機播放、列表播完自動切下一首。載入失敗顯示錯誤，可重新選曲重試，避免每幀重複載入。

## 9. 主要實作位置與複雜度

`domain/rule/CampaignBalance.java`：人口、徵兵成本、有效民心、新兵士氣及年變化上限。
`OfficerCommandProfile.java`：抽象武將能力。
`NationalActionPointRules.java`／`FactionActionPointRules.java`：總民心與玩家／AI 額度。
`RecruitmentRules.java`／`TroopQualityRules.java`／`PopulationRules.java`：三條核心計算。
`DomesticActionService.java`：共用套用；Application Command 保留 copy-on-write 及安全保存。
`CityScreen.java`／`assets/ui/city.xml`：徵兵 modal、預估與小數顯示。
`MusicPlaybackController.java`／`SangoAudioService.java`：轉場、暫停與資源生命週期。
`MusicPlayerScreen.java`／`assets/ui/music_player.xml`：音樂鑑賞。

單次人口上限與品質計算 O(1)。民心彙總 O(C)，目前每城人口計算會重查其勢力平均，年度最壞 O(C²)；C=42 時規模小，沒有假稱已做 O(C) 全局快取。AI 約 O(F×AP×C) 加上前線連線搜尋。音樂混音至多保留枚舉中有限曲目，穩態一個串流；快速反覆切換期間可能短暫多於兩個。戰報無上限、copy-on-write 與存檔量隨歷史增加的既有限制保留。
